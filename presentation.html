Orchestration & State Management
Turn Lifecycle & Two-Tier Memory Architecture
Turns are serialized inside a Cloudflare Durable Object with zero cross-customer context leakage.
Turn Orchestration Pipeline
  • 1. Ingestion & Credit Gate: Turn credits verified to prevent runaway token spend.
  • 2. Customer Isolation Check: If customerId changes, DO wipes state and resets transcript.
  • 3. Lazy Profiling Dispatch (S1.6): Computes segment on Turn 1 if missing.
  • 4. Intent Classification (S1.4): LLM Gateway classifies intent with 4-turn history.
  • 5. Agent Dispatch: Invokes specialized agent with declared MCP contracts.
  • 6. Inline Policy Guardrail: Evaluates pure TypeScript predicates before replying.
Two-Tier Memory Separation
  • Tier 1: Within-Session (Durable Object Storage):
    • Turn history with detected intents & timestamps
    • Working customer segment & evidence
    • Last viewed SKU & category
    • Pending upsell offer state (survives worker deploys!)
  • Tier 2: Across-Session (Cloudflare D1 context_store):
    • Long-term segment & propensity scores
    • Confirmed size & fit recommendations
    • Active subscription entitlements (Plus/Premium)
Agent #1: Profiling & Segmentation (M3 Sequence 1)
Deterministic Affluence & PII Minimisation
Profiles customers live on Turn 1 from observable purchase patterns without using protected attributes.
Objective Scoring Formula
Affluence = 0.40*(AUP/120) + 0.35*(PremShare/0.60) + 0.25*(Spend/3500)
  • AUP Score (40%): Avg Unit Price vs £120 ceiling.
  • Premium Share (35%): Share of premium SKUs vs 60% benchmark.
  • Annual Spend (25%): Trailing 12-month spend vs £3,500.
  • Classification Bands:
    • ≥ 0.62 → Affluent (Priya C001: 0.77)
    • ≥ 0.32 → Mid (Arjun C004: 0.44)
    • < 0.32 → Value-Seeking (Aditi C002: 0.18)
Inline Policy Guardrail: PII Minimisation
  • The Privacy Mandate: No raw identifiers (names, emails, phone numbers, cities) may ever travel to an external LLM.
  • Inline Execution: Evaluated via piiMinimisation() before context write-back.
  • Safe Model Payload: Downstream agents receive ONLY derived mathematical features:
    { affluence: 'affluent', aup: 114.20, tenure_days: 340 }
  • Immutable Audit: Pass/block decision logged to Cloudflare Analytics Engine.
Agent #2: Discovery & Recommendation (M3 Sequence 2)
Personalised Ranking with Algorithmic Fairness
Same query returns different products for affluent vs value customers, while guaranteeing equal access.
Multi-Factor Objective Function
Score = Relevance + TierW*0.5 + Rating*0.35 + StockBoost + FitBoost - ReturnRate*1.2
  • Affluent Tier Weights: Premium (3.0x), Core (1.6x), Value (0.2x).
  • Value Tier Weights: Value (3.0x), Private Label (2.6x), Premium (0.3x).
  • Fit-Aware Boost: +0.6 boost if customer's known size is in stock.
  • Return Penalty: SKUs with high return history down-weighted (-1.2x).
Fairness Guardrail: "Ranking differs, access does not"
  • 1. Identical Eligibility: Candidate pool size must be 100% equal across segments. Zero catalog redlining.
  • 2. Diversity Floor: Enforces ≥2 price tiers in top 10 to prevent algorithmic exclusion.
  • 3. Neutral Comparator: Verified against neutral sorting (relevance/rating).
  • 4. Live Demo Toggle: Passing unsafeRanking: true skips diversity floor; guardrail visibly BLOCKS and serves neutral ranking!
Agent #3: Size & Fit Personalisation (M3 Sequence 3)
Anthropometric Sizing Science & The Abstain Rule
The direct lever on 58% of the returns crisis, combining empirical distributions with strict consent.
1. Strict Consent Gate
  • Body measurements are strictly confidential.
  • Checked via fitConsent() before reading any metrics.
  • If consent is false, measurements are blocked.
  • Degrades to standard size guide.
2. 120k Anthropometrics
  • Grounded on 120,000 real sizing rows (fitment_dat.csv).
  • Calculates Z-score distance:
    Δ = (|H - μh|/σh + |W - μw|/σw)/2
  • Adjusts for brand cut (runs_small, runs_large, relaxed).
3. The 70% Abstain Rule
  • Confidence scorecard:
    +5 per kept purchase, +20 for low Z-distance, -12 per prior return.
  • If confidence < 70% → ABSTAIN!
  • Wrong recommendations create returns. Silence protects margin.

Objective 3 Compliance
Eight Deliberate Blueprint Deviations
Calling out where the build improved on the M3 blueprint shows senior engineering judgment.
1. Durable Objects over Memory Maps
Blueprint named Context Manager. We replaced single-process Maps with Cloudflare Durable Objects. Sessions are serialized, survive deploys, and eliminate customer context leaks.
2. Synchronous Bindings over Kafka
Blueprint proposed Kafka bus. We substituted zero-latency Worker Service Bindings. Async paths are preserved without Kafka operational overhead at the edge.
3. TypeScript Predicates over Rego/OPA
Policy-as-code is implemented as pure TypeScript predicates. Same guarantee: evaluated inline, agent cannot overrule, and trace is permanently recorded.
4. Both Monetization Agents Built
Brief permitted selecting Upsell OR Loyalty. We built both to definitively prove cross-agent memory handoff (Loyalty reads Upsell's written entitlement for 2x multiplier).

Judge Defense Cheat Sheet
Anticipated Technical Questions & Winning Answers
Pre-empting tough questions with platform evidence and architectural proofs.
Q1: "Can an agent perform SQL injection or dump customer data?"
Answer: Platform capability denial. Look at wrangler.jsonc—3 of the 4 Workers have NO D1 binding. The agent runtime does not possess a database handle. Platform security beats prompt instructions.
Q2: "Does affluence ranking discriminate against lower-income shoppers?"
Answer: "Ranking differs, access does not." Our fairness guardrail mathematically guarantees identical candidate pool eligibility and enforces multi-tier diversity. Any exclusion triggers an automatic fallback to neutral ranking.
Q3: "What happens if OpenAI or Anthropic goes down during shopping?"
Answer: Graceful edge degradation. The LLM Gateway catches upstream timeouts, falls back to deterministic mock output with degraded: true, and never breaks the customer shopping session.
