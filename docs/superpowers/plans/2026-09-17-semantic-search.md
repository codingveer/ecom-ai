# Opt-In Semantic Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in, embedding-backed semantic retrieval path to `catalogue.search` (Workers AI + Vectorize), selectable per request via `searchMode: "semantic"`, alongside the existing lexical path which stays the unchanged default — so the demo can run the same fuzzy query through both and show the delta live.

**Architecture:** New `AI` and `vectorize` bindings on `services` only (the Worker that already owns `catalogue.search`'s implementation) — `tools`, `llm`, `app` bindings are untouched. Product descriptions are generated deterministically at seed time (no LLM call), embedded via Workers AI (`@cf/baai/bge-base-en-v1.5`) into a Vectorize index by a one-time `/catalogue/reindex` endpoint, then queried at search time with a try/catch fallback to lexical scoring (`degraded: true`) if the embedding/vector call fails. The toggle threads through the same call shape `unsafeRanking` already uses: request body → `session-do.ts` → `discovery.rank()` → tool invoke arg.

**Tech Stack:** Cloudflare Workers AI (`@cf/baai/bge-base-en-v1.5`, 768-dim), Cloudflare Vectorize (cosine metric), existing Hono services Worker, existing D1. No new npm dependencies.

**Reference design doc:** `docs/superpowers/specs/2026-09-17-semantic-search-design.md`

## Global Constraints

- Default behavior (`searchMode` omitted, `semanticSearch` omitted) must produce identical candidate filtering, scoring and ranking to the current lexical `catalogue.search` — no regressions to `npm run smoke`, which stays on the deterministic mock-LLM path and is not modified. (Amended after Task 2's review: this does not forbid the additive top-level `mode: "lexical"` field Task 2 deliberately adds to every response including the default path — see the design spec's Section D, "a top-level `mode` field... so the trace and demo console can show which path actually served a given call." The original "byte-for-byte identical... response shape" wording was imprecise; no consumer in this codebase depends on the exact response shape, confirmed during Task 2's review.)
- Only `packages/services` gains new bindings (`AI`, `vectorize`/`VECTORS`). `packages/tools`, `packages/llm`, `packages/app`'s `wrangler.jsonc` files are not touched.
- No LLM/network call during `npm run gen` — product description text is generated by deterministic TypeScript templating in `scripts/gen-seed.ts`, fully reproducible offline.
- `ToolContract.input_schema` (`packages/tools/src/types.ts`) has no enum support — `searchMode` is typed `"string"`; any value other than the literal `"semantic"` is treated as lexical server-side.
- Workers AI and Vectorize have no local simulator — both always call the real Cloudflare API even under plain `npm run dev`. This feature requires a logged-in `wrangler`/API token; it is not required to work fully offline.
- Preserve the `m3_ref: 'S2.7'` trace tag on the `catalogue.search` invoke in `discovery.ts` — this is the same logical retrieval step with a swapped backend, not a new step.

async function lexicalSearch(env: Env, terms: string[], category: string | null, limit: number) {
  const stmt = category
    ? env.DB.prepare(`
        SELECT p.*, COALESCE((SELECT SUM(qty) FROM inventory v WHERE v.sku = p.sku),0) stock
        FROM products p WHERE p.category = ?`).bind(category)
    : env.DB.prepare(`
        SELECT p.*, COALESCE((SELECT SUM(qty) FROM inventory v WHERE v.sku = p.sku),0) stock FROM products p`);
  const { results } = await stmt.all();

  return (results as any[]).map(r => {
    const hay = `${r.title} ${r.category} ${r.style_tags} ${r.material} ${r.colour}`.toLowerCase();
    let score = 0;
    for (const t of terms) {
      if (hay.includes(t)) score += 2;
      if (String(r.category).toLowerCase().startsWith(t.replace(/e?s$/, ''))) score += 3;
      if (String(r.style_tags).toLowerCase().includes(t)) score += 2;
    }
    return { ...r, relevance: score };
  }).filter(r => (terms.length === 0 ? true : r.relevance > 0) && r.stock > 0)
    .sort((a, b) => b.relevance - a.relevance || b.rating - a.rating)

async function semanticSearch(env: Env, q: string, category: string | null, limit: number) {
  const embedded = await env.AI.run(EMBED_MODEL as any, { text: [q] }) as any;
  const vector = embedded.data[0] as number[];
  const topK = Math.min(limit * 3, 100);
  const matches = await env.VECTORS.query(vector, {
    topK, returnMetadata: 'none', // 'none', not `false` - the boolean form mis-serializes through
    // wrangler/workerd's remote-bindings proxy into invalid JSON for the real Vectorize REST API
    // (VECTOR_QUERY_ERROR 40026, found during Task 3's real-API verification); the string-enum
    // form (`VectorizeQueryOptions.returnMetadata?: boolean | 'all' | 'indexed' | 'none'`) works.
    filter: category ? { category } : undefined,
  });
  const ids = matches.matches.map(m => m.id);
  if (!ids.length) return [];

  const stmt = env.DB.prepare(`
    SELECT p.*, COALESCE((SELECT SUM(qty) FROM inventory v WHERE v.sku = p.sku),0) stock
    FROM products p WHERE p.sku IN (${ids.map(() => '?').join(',')})`).bind(...ids);
  const { results } = await stmt.all();

  const scoreBySku = new Map(matches.matches.map(m => [m.id, m.score]));
  return (results as any[])
    .map(r => ({ ...r, relevance: r2((scoreBySku.get(r.sku) ?? 0) * 10) }))
    .filter(r => r.stock > 0)
    .sort((a, b) => b.relevance - a.relevance);
}

app.get('/catalogue/search', async c => {
  const q = (c.req.query('q') ?? '').toLowerCase().trim();
  const category = c.req.query('category') ?? null;
  const limit = Number(c.req.query('limit') ?? 40);
  const terms = q.split(/\s+/).filter(Boolean);
  const searchMode = c.req.query('searchMode') === 'semantic' ? 'semantic' : 'lexical';

  if (searchMode === 'semantic') {
    try {
      const results = await semanticSearch(c.env, q, category, limit);
      return c.json({ query: q, candidates: results.length, results, mode: 'semantic' });
    } catch (err) {
      const results = await lexicalSearch(c.env, terms, category, limit);
      return c.json({
        query: q, candidates: results.length, results, mode: 'lexical', degraded: true,
        degraded_reason: err instanceof Error ? err.message : 'semantic search unavailable',
      });
    }
  }

  const results = await lexicalSearch(c.env, terms, category, limit);
  return c.json({ query: q, candidates: results.length, results, mode: 'lexical' });
});
```

This reuses the file's existing `r2` helper (`packages/services/src/index.ts:14`, `const r2 = (n: number) => Math.round(n * 100) / 100;`) to scale a 0..1 cosine score into roughly the same numeric range as lexical's integer-ish relevance scores, so `discovery.ts`'s scoring formula needs no changes.

app.post('/catalogue/reindex', async c => {
  const { results } = await c.env.DB.prepare(`SELECT sku, category, description FROM products`).all();
  const rows = results as { sku: string; category: string; description: string }[];

  const EMBED_BATCH = 20;
  const UPSERT_BATCH = 200;
  const toUpsert: VectorizeVector[] = [];

  for (let i = 0; i < rows.length; i += EMBED_BATCH) {
    const chunk = rows.slice(i, i + EMBED_BATCH);
    const embedded = await c.env.AI.run(EMBED_MODEL as any, { text: chunk.map(r => r.description) }) as any;
    const vectors: number[][] = embedded.data;
    chunk.forEach((r, idx) => toUpsert.push({ id: r.sku, values: vectors[idx], metadata: { category: r.category } }));
  }

  for (let i = 0; i < toUpsert.length; i += UPSERT_BATCH) {
    await c.env.VECTORS.upsert(toUpsert.slice(i, i + UPSERT_BATCH));
  }

  return c.json({ indexed: toUpsert.length });
});
```

(`VectorizeVector` is another ambient global type from `@cloudflare/workers-types`, same as `VectorizeIndex` — no import needed.)
